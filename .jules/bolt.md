## 2026-03-06 - FlowField Typed Array Buffer Reuse & Avoiding Reference Aliasing
**Learning:** In high-frequency game AI pathfinding (`FlowField`), re-allocating `Float32Array` and `Int32Array` buffers on every `rebuild()` creates thousands of GC allocations per second. Reusing pre-allocated typed arrays and static directional offsets (`DX`, `DY`) completely eliminates BFS allocation overhead. When optimizing query functions like `dir()`, returning a shared mutable internal object instance introduces reference aliasing risks across call sites; accepting an optional output target parameter (`out?: {x: number; y: number}`) is a safer allocation-free pattern.
**Action:** Always reuse pre-allocated typed array buffers for BFS/pathfinding engines, use static directional offset constants instead of inline array literals, and avoid returning shared mutable state from query methods unless using explicitly provided output target objects.
